# 206 — 아이템 · 인벤토리 · 가방 · 로프/피톤

> 기획 근거: `100_game_design.md` 5.3·9장. 상태이상 적용은 `202` 6장, 네트워크 권한은 `205` 3장.
> 소유 폴더: `Scripts/Runtime/Items/`, `Data/ItemDef/`, `Prefabs/Items/`. 마일스톤: M3 (음식·붕대·가방), M5 (나머지 T1 아이템).

## 1. `ItemDef` (ScriptableObject)

| 필드 | 뜻 |
|---|---|
| `id` | 문자열 키 (`rope`, `bandage` …) |
| `displayName` | 한국어 이름 |
| `weight` | 0 / 2.5 / 5 → 무게 상태이상 |
| `useMode` | `Instant`(즉시) / `Hold`(N초 홀드) / `Place`(바닥·벽에 설치) / `Throw`(투척) / `Wear`(착용) / `Passive`(소지 효과) |
| `useDuration` | Hold 시간 |
| `targetable` | 바라보는 팀원에게 사용 가능한가 |
| `effects[]` | `(StatusKind, amount, isRemove)` 목록 — 사용 시 대상에게 적용 |
| `bonusStamina` | 보너스 스태미나 부여량 |
| `consumeOnUse` | 소모품 여부 / `uses` 횟수 |
| `prefab` | 월드·손 프리팹 (Root + Visual, `102`) |
| `spawnWeight[biome]` | 가방 내용 추첨 가중치 |
| `cookedVariant` | T2 요리 결과 (`101` 3장) |

## 2. 인벤토리 (`Inventory`, 플레이어 컴포넌트)

- 슬롯: 손 슬롯 `n_slots` (초기값 3 ⚠) + 배낭 슬롯 1 (배낭 아이템만). 배낭 착용 시 배낭 내부 4슬롯 (Tab 으로 열어 손 슬롯과 교환)
- 들고 있는 아이템 표시 (1인칭, `301` D16)
  - **T0**: HUD 슬롯 강조만 (`204` 2.2). 화면에 들고 있는 모습 없음
  - **T1 (M5)**: 오너 화면 = 1인칭 손 뷰모델(`202` 12.3)의 오른손에 아이템 `Visual` 축소본. 다른 플레이어 화면 = 몸 오른쪽 소켓에 아이템 `Visual`. 등반 중에는 둘 다 숨김
  - 아이템 프리팹은 `Visual` 을 뷰모델용·월드용으로 따로 두지 않는다. 같은 `Visual` 을 복제해 부착하고 스케일만 다르게 한다
- 조작: `1~3` 선택, `UseItem` 사용, `Q` 버리기(앞으로 살짝 던짐), `E` 줍기
- 무게: 슬롯 변화 시 `Σ weight` → `StatusEffectStack.Set(Weight, …)` (배낭 안 아이템 포함)
- 네트워크: 슬롯 내용은 `NetworkList<ItemSlot(itemNetId, defId)>`. 줍기·버리기·사용은 `ServerRpc` 요청, 호스트가 오브젝트 소유·부모 처리. 사용 효과는 대상 오너에게 (`205` 3장)
- 기절·사망 시: 사망은 전부 드롭, 기절은 유지

## 3. 가방 (`Luggage`)

- 생성 단계에서 위치와 **내용 시드** 결정 (`203` 4.4). 내용 = `new Random(contentSeed)` 로 `BiomeDef` 의 아이템 가중치에서 2~4개 추첨 → 호스트·클라이언트 동일. 실제 스폰은 호스트만 (`205` 3장)
- 상호작용 E → 열림(색 변화) → 아이템이 가방 앞에 떨어짐
- 시작 플랫폼 가방 3개는 고정 내용: [붕대×2, 음식×2], [로프, 음식], [피톤, 붕대] ⚠ (T0 은 로프·피톤 없이 붕대·음식)
- 원작 아이템 출처 중 "나무 열매·버섯을 직접 따기"는 T2. 코어는 가방만

## 4. 코어 아이템 사양

| 아이템 | useMode | 효과 | 무게 | 티어 | 구현 메모 |
|---|---|---|---|---|---|
| **음식** (통합: 열매/통조림) | Instant, targetable | 허기 −30 ⚠, 종류별 보너스 +5. 변종 "독 열매": 허기 −30 + 독 +20 (색으로 구분) | 2.5 | T0 | 데이터만 |
| **붕대** | Hold 2s, targetable | 부상 −30 | 2.5 | T0 | 데이터 + 홀드 진행 바 |
| **로프 스풀** | Place (발판 가장자리) | 앵커에서 아래로 10 m 로프 | 2.5 | T1 | 4.1 |
| **피톤** | Place (벽) | 벽에 고정, 잡으면 회복 (1명) | 2.5 | T1 | 4.2 |
| **랜턴** | Passive (선택 슬롯에 있을 때) | 반경 3 m 추위 −5/s, 포인트 라이트 | 5 | T1 | 손에 들고 있어야 함 (원작 동일) |
| **배낭** | Wear | 슬롯 +4 | 0 | T1 | 2장 |
| **조명탄** | Instant (정상 표식 근처에서만) | 클리어 트리거. 다른 곳에서는 붉은 연기(신호) | 0 | T1 | 표식 반경 5 m 판정 |
| **스카우트 인형** | Place | 사용 위치에 사망자 1명(무작위) 부활. 사망자 없으면 소모만 (원작 동일) | 5 | T1 | `ServerRpc` → 호스트가 대상 선택·리스폰. 솔로 세션에서는 가방에서 안 나옴 |

### 4.1 로프

- 설치: 플레이어가 발판 가장자리(전방 1 m 아래가 벽)에 서서 사용 → 앵커 오브젝트 + 아래로 늘어진 로프
- **v1 = 물리 없음**: 앵커에서 수직 아래로 최대 `ropeLength`(10 m), 벽에 닿기 전까지. 벽 경사를 따라 붙도록 0.5 m 간격으로 표면 레이캐스트해 점 목록 생성 (결정적 — 호스트가 계산해 점 목록을 스폰 데이터로 전송, 또는 앵커+방향만 전송하고 각자 같은 계산 ⚠ `301` Q6)
- 표현: `LineRenderer` + 각 세그먼트 캡슐 콜라이더(레이어 `Rope`)
- 잡기: `ClimbSensor` 가 `Rope` 레이어를 우선 탐지 → `Hanging` 상태. 상하 이동 `ropeSpeed` 2 m/s, 소모 `ropeCost` 4/s. **정지 시 회복 50%** ⚠ 확인 필요
- 로프 끝에서 위로 → 앵커 발판에 맨틀. 아래로 → 떨어짐/착지
- v2 (T2): Verlet 체인 물리, 흔들기, 로프 캐논

### 4.2 피톤

- 설치: 벽에 붙어(Climbing) 사용 → 표면에 고정 오브젝트
- 잡기: 근접 시 E → `Hanging(Piton)` 상태: 위치 고정, **스태미나 회복 full**. 한 번에 1명 (점유 `NetworkVariable`)
- 이탈: Climb 홀드로 다시 벽으로, 또는 놓기

## 5. 사용 대상 규칙

- `targetable` 아이템은 조준 대상이 팀원(2.5 m 이내)이면 **그 팀원에게** 적용, 아니면 자기에게
- 기절자에게도 사용 가능 (이것이 구조의 핵심 — `100` 4.4)
- 사용 중(Hold) 이동하면 취소

## 6. 아이템 프리팹 규칙

```
Item_<id> (NetworkObject, Rigidbody, Collider, ItemInstance{def})
 └─ Visual (프리미티브, 102)
```

- 바닥에 있을 때: Rigidbody 활성, 호스트 물리 → `NetworkTransform`(호스트 권한)
- 인벤토리 안: Rigidbody/Collider 비활성, 플레이어 손 소켓에 부모. 오너십 = 플레이어
- 던지기: `ServerRpc(dir)` → 호스트가 분리·힘 적용

## 7. 테스트 (M3·M5 게이트)

- [ ] 가방 열기 → 같은 시드에서 호스트·클라이언트가 같은 아이템 목록 (로그 비교)
- [ ] 음식·붕대를 자기·팀원·기절자에게 사용 → 상태이상 감소
- [ ] 무게 합이 바에 회색 조각으로 보이고 버리면 사라짐
- [ ] 로프를 설치하면 아래 사람이 잡고 올라온다. 로프 위에서 멈추면 회복
- [ ] 피톤을 박고 매달리면 회복, 두 번째 사람은 잡을 수 없다
- [ ] 조명탄을 정상에서 쓰면 클리어, 다른 곳에서는 연기만
- [ ] 인형으로 부활한 플레이어가 빈 인벤토리·초기 상태로 그 자리에 나타난다
