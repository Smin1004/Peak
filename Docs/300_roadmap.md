# 300 — 로드맵 (티어 · 마일스톤 · 게이트 · 컷 라인 · 리스크)

> 1인 + AI 워커, 기간 미정, "최대한 빨리". 그래서 **언제 멈춰도 플레이 가능한 상태**를 유지하는 것이 이 문서의 목적이다.
> 규모 추정은 ⚠ 전부 확인 필요 — 1인 + 워커 세션 기준 감. 실제 소요를 12장에 기록해 보정한다.

## 1. 티어 (다시)

| 티어 | 성립 조건 | 필요한 마일스톤 |
|---|---|---|
| **T0 학습용 최소** | 혼자 절차 생성 산을 20분 재밌게 오른다 | M0 ~ M3 |
| **T1 협동 MVP** | 친구와 온라인으로 한 판 완주 | + M4 ~ M5 |
| **T2 완성작** | 원작 경험의 재현 | + M6 (개방형) |

## 2. 마일스톤

| M | 이름 | 목표 (한 문장) | 근거 문서 | 규모 ⚠ |
|---|---|---|---|---|
| M0 | 프로젝트 골격 | 아무 씬에서 플레이를 누르면 호스트로 뜨고 캡슐이 걷는다 | 201, 205 6장, 204 4장 | 1~2일 |
| M1 | 등반 프로토타입 | 손으로 만든 벽에서 등반·스태미나·낙하가 "재밌다" | 202 | 2~4일 |
| M2 | 절차 생성 v1 | 시드 100개가 전부 등반 가능하고, 시드 1을 M1 캐릭터로 정상까지 오른다 | 203 | 4~7일 |
| M3 | 런 루프 (싱글) = **T0** | 해변 → 캠프파이어 → 정상, 허기·부상·가방·기절·결과 화면 | 100 3·4·7장, 206 3·4장, 204 | 3~5일 |
| M4 | 온라인 협동 | 참가 코드로 붙은 2~4명이 같은 산에서 집결·점화·구조·부활한다 | 205, 100 10장 | 4~7일 |
| M5 | T1 콘텐츠 = **T1** | 바이옴 3 + 정상, 안개, 로프·피톤·랜턴·배낭·조명탄·인형, 위험 구역 | 100 6·8·9장, 203 5장, 206 4장 | 4~7일 |
| M6 | T2 | 101 의 항목을 우선순위대로 | 101 | 개방형 |

### M0 — 프로젝트 골격

산출물:
- 패키지 추가·제거 (`201` 1.1), 템플릿 잔재 삭제
- 폴더 구조 + asmdef 3개 (`201` 3장)
- 씬: Boot, Lobby(싱글 시작 버튼만), Game(빈 지면 평면), Sandbox_Climb, Sandbox_ProcGen
- `Bootstrapper`: 어느 씬이든 플레이 → Boot 로드 → `StartHost()` (`205` 6장) ⚠ Q1
- `PeakActions.inputactions` (`202` 1장)
- `GameTuning`, `VisualTheme` 에셋 + 로더
- Player 프리팹: NetworkObject + 캡슐 + 걷기·달리기·점프 + 오빗 카메라 (등반 없음) + Visual 분리
- 디버그 오버레이 F3 (`204` 4장), `Log` 래퍼
- **게이트**: Game 씬 플레이 → 호스트로 실행, 캡슐이 걷고 점프하고 카메라가 돈다. 콘솔 에러 0

### M1 — 등반 프로토타입

산출물: 상태 기계, `ClimbSensor`, `StaminaSystem`, `StatusEffectStack`(허기·부상만), `FallDamage`, 스태미나 바 HUD, `Sandbox_Climb` 벽 세트 (경사 45/60/75/85°, 높이 5/10/15/20 m, 볼록·오목 코너, 모서리)
- **게이트**: `202` 10장 체크리스트 전부. 특히 마지막 항목(재미)이 안 되면 M2 로 가지 않는다 — 등반이 재미없으면 산을 잘 만들어도 소용없다
- 컷 가능: 앉기, 맨틀 애니메이션(순간이동으로 대체)

### M2 — 절차 생성 v1

산출물: `203` 4장 파이프라인 전부 + 10장 디버그 도구 + 11장 테스트. `BiomeDef` Shore·Peak 초기값 확정 (T0 시퀀스)
- **게이트**: `203` 12장. 시드 1 을 정상까지 (캠프파이어 없이, 허기 OFF 로)
- 컷 가능: 미끼 분기(Decoy), 노이즈 정교화, 정점 색. 컷 불가: 솔버·보정·결정성

### M3 — 런 루프 싱글 (T0)

산출물: 캠프파이어(점화 조건·효과·반경 안전), 허기 티커, 가방·음식·붕대·인벤토리·무게, 기절/사망(싱글 규칙), 정상 표식 → 결과 화면, Lobby 싱글 시작(시드 입력), 안개(구현하되 기본 OFF)
- **게이트**: T0 완주. 20분 플레이 후 "한 판 더" 가 나오는가 (주관, 본인 + 가능하면 1명)
- 컷 가능: 안개(M5 로), 결과 화면 통계

### M4 — 온라인 협동

산출물: `NetService`(Sessions + Relay), Room UI, 생성 동기화·해시, 플레이어 상태 복제, 타인 대상 아이템 사용, 업기, 집결 점화, 인형 부활, 유령·채팅, 팀원 마커, 호스트 이탈 처리
- **게이트**: `205` 7장 시나리오 전부
- 컷 가능: 채팅(디스코드), 유령 자유 비행(팀원 고정 카메라로)

### M5 — T1 콘텐츠

산출물: Jungle·Alpine `BiomeDef` + 위험 구역(독 열매, 벌집, 추위 구역), 로프·피톤·랜턴·배낭·조명탄, 안개 기본 ON + 튜닝, T1 시퀀스 한 판 30~50분 튜닝, 결과 화면 완성
- **게이트**: 친구와 T1 한 판 완주. 안개에 쫓기는 순간이 한 번 이상 있다
- 컷 가능: 벌집(추격 없음이므로 쉬움, 그래도 후순위), 랜턴(추위 구역을 줄이면 됨)

### M6 — T2 (개방형)

`101` 순서 권고: Ascent 1·2·3·6 (배율) → 요리 → Mesa → 확장 아이템 → 배지/코스메틱 → 일일 시드 → Roots/Gloom/Citadel → 래그돌 → 오버행 v2 → 낮/밤

## 3. 순서의 근거

- **M1 이 M2 보다 먼저**: 등반 수치(`ClimbBudgetHeight`)가 생성기 파라미터를 결정한다. 조작감 없이 산을 만들면 두 번 만든다
- **M2 가 M3 보다 먼저**: 프로젝트 계기가 절차 생성. 가장 불확실하고 가장 재밌는 부분을 먼저 검증해 "이 프로젝트가 될지" 를 일찍 안다
- **M4 가 M5 보다 먼저**: 협동 아이템(로프·인형·업기)은 멀티 없이는 테스트가 안 된다. 네트워크 위에 콘텐츠를 얹는다
- **M0 에서 NGO 를 켜는 이유**: `205` 1장. 반대 의견이면 `301` Q1 에서 결정

## 4. 컷 라인 (시간이 없을 때 어디서 멈추는가)

| 멈추는 시점 | 갖게 되는 것 | 마무리 작업 |
|---|---|---|
| M2 끝 | 절차 생성 산 + 등반 (게임 아님) | Sandbox_ProcGen 을 "데모"로: 시드 입력 → 오르기 |
| **M3 끝 = T0** | 싱글 등반 게임 | 결과 화면, README |
| M4 끝 | 온라인 협동 (바이옴 1) | 안개 ON 만 켜면 협동 긴장 확보 |
| **M5 끝 = T1** | 협동 MVP | 튜닝 |
| M6 중 | T2 일부 | 각 항목이 독립이라 어디서 멈춰도 됨 |

## 5. 워커 발행 단위

- 한 워커 = 한 마일스톤의 **한 폴더** 또는 **한 산출물**. 예: M1 은 (a) 상태 기계 + ClimbSensor, (b) Stamina + StatusEffect + FallDamage, (c) 스태미나 바 HUD, (d) Sandbox_Climb 벽 세트 — a·b 는 인터페이스가 얽히므로 순차, c·d 는 병렬 가능
- 워커 프롬프트는 브레인이 `201` 8장 형식으로 작성. 완료 보고를 브레인이 검토 → 문서 갱신 → 커밋(사람)
- 병렬 워커는 폴더가 겹치지 않을 때만 (`201` 8장)
