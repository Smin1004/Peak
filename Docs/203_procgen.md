## 2. 접근 비교와 선택

| 접근 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 노이즈 지형 생성 후 검증·재시도 | 구현 단순, 자연스러움 | 등반 가능 보장이 확률적. 재시도 비용 | 기각 |
| B. 손으로 만든 청크 조립 (WFC 류) | 100% 보장, 품질 제어 | 청크 제작 = 아트 작업. 1인에 부담. 반복감 | 기각 (T2 특수 구조물에는 부분 사용 가능) |
| **C. 경로 우선 (route-first)** — 등반 경로 그래프를 먼저 만들고 지형을 그 위에 씌운 뒤 솔버로 검증·보정 | 보장 + 다양성. 파라미터로 바이옴 표현 | 지형 표현이 경로에 종속 (스탬프 티가 남) | **채택** |

C 의 핵심 아이디어: **"쉬는 발판(ledge)" 사이의 벽 높이가 스태미나 한 번으로 오를 수 있는 높이 이하**이면 등반 가능하다. 발판 = 그래프 노드, 벽 = 간선.

## 3. 파이프라인

```
RunConfig(seed, biomes)
   │
   ├─ ① 산 뼈대      바이옴 밴드 높이·경사 → 원뿔 프로필 R(h), 캠프파이어 플랫폼 각도
   ├─ ② 경로 그래프   플랫폼 → 플랫폼 노드 체인 (나선 + 흔들림) + 막다른 분기 + (T2) 로프 지름길
   ├─ ③ 하이트맵      기본 원뿔 + 노이즈 → 노드마다 발판 스탬프 → 플랫폼 스탬프
   ├─ ④ 배치         가방·위험 구역·정상 표식·시작점
   ├─ ⑤ 솔버 검증     실제 하이트맵 위에서 간선별 등반 비용 계산 ≤ 예산
   ├─ ⑥ 보정         실패 간선에 중간 노드 삽입 → ③ 부터 재실행 (최대 N회) → 그래도 실패면 seed+1 (로그)
   └─ ⑦ 메시 빌드     청크 메시 + MeshCollider + 정점 색
```

각 단계는 `System.Random` 을 **자기 스트림**으로 받는다: `rng_k = new Random(Hash(seed, k))`. 한 단계의 난수 소비량이 바뀌어도 다른 단계가 흔들리지 않는다 (7장).

## 4. 단계 상세

### 4.1 산 뼈대

- 좌표: 산 중심 = 원점, 위 = +Y. 하이트맵은 XZ 격자 `h(x, z)`, 셀 1 m ⚠ (0.5 m 는 성능 확인 후)
- 바이옴 밴드 `b` 는 높이 `[h_b0, h_b1)`, 높이 `H_b`, 평균 경사 `s_b`. 원뿔 반경 프로필은 밴드별 직선: `R(h)` 는 `h_b0` 에서 `h_b1` 까지 반경이 `H_b / tan(s_b)` 만큼 줄어든다
- `R_base = R_top + Σ H_b / tan(s_b)`. T1 예 (⚠): Shore 50 m/55° + Jungle 100 m/70° + Alpine 120 m/75° + Peak 40 m/80° + R_top 10 → R_base ≈ 120 m → 격자 260×260
- 해수면 `y = 0`. 해변 밴드는 `y = 0` 에 폭 15 m 의 평탄 링 (시작 지역). 링 밖 = 바다 (즉사 구역 `100` 4.4)
- 캠프파이어 플랫폼: 밴드 경계 높이 `h_b1` 마다 1개. 각도 `θ_camp[b]` = 이전 플랫폼 각도 + `rng` 로 뽑은 `[90°, 270°]` (반 바퀴 안팎 돌게). 플랫폼 = 반경 22 m 평탄 디스크 (캠프파이어 반경 19 m 포함)
- 정상 플랫폼: `h = H_total`, 반경 `R_top`, 정상 표식

### 4.2 경로 그래프 (`RouteGraph`)

노드 = 발판 (위치 `(x, z)`, 높이 `h`, 반경 `r_ledge`, 종류: Platform / Ledge / Decoy). 간선 = 등반 구간 (A → B, 종류: Main / Decoy / RopeShortcut).

플랫폼 `P_b` 에서 `P_{b+1}` 까지 메인 체인 생성:

```
h ← h(P_b);  θ ← θ(P_b);  prev ← P_b
while h < h(P_{b+1}) − Δh_min:
    Δh ← rng.Range(Δh_min, Δh_max_b)          // 바이옴별, 단 Δh_max_b ≤ ClimbBudgetHeight × safety
    Δθ ← sign × rng.Range(Δθ_min, Δθ_max)      // 나선 방향 sign 은 밴드마다 고정, 가끔 반전(rng)
    h ← h + Δh;  θ ← θ + Δθ
    pos ← (R(h)·cos θ, R(h)·sin θ)              // 원뿔 표면 위
    측면 거리 lateral = |pos − prev.pos|_xz 가 L_max 초과면 Δθ 축소
    node ← Ledge(pos, h, r_ledge ← rng.Range(r_min, r_max))
    edge(prev → node, Main);  prev ← node
edge(prev → P_{b+1}, Main)
```

- `ClimbBudgetHeight = (100 / climbCost) × climbSpeed` (`GameTuning`) — 초기값 15 m. `safety` 0.7 → `Δh_max ≤ 10.5 m`. 바이옴별 `Δh_max_b` 는 이 이하에서 난이도 표현 (Shore 6, Jungle 8, Alpine 10 ⚠)
- 노드 간 최소 수평 간격 `2·r_max + 2 m` (스탬프 겹침 방지). 위반 시 Δθ 재추첨
- **막다른 분기 (Decoy)**: 메인 노드마다 확률 `p_decoy_b` 로 옆으로 1~2 노드 가지를 낸다. 마지막 노드 위 벽은 `Δh > ClimbBudgetHeight` 가 되도록 다음 발판을 두지 않는다 (G6)
- **로프 지름길 (T2)**: 메인 노드 A 에서 두세 노드 위 B 로 `Δh ≤ ropeLength(10 m)` 이면서 `Δh > Δh_max_b` 인 직행 간선. 솔버는 무시 (솔로 보장은 메인 체인)
- 결과: 밴드당 노드 수 ≈ `H_b / 평균 Δh` (Jungle 100 m ÷ 7 ≈ 14 노드)

### 4.3 하이트맵 (`HeightField`)

1. **기본 원뿔**: `h_base(x, z) = R⁻¹(r)` — 반경 → 높이 역함수 (밴드별 직선이므로 닫힌 형태)
2. **노이즈**: 능선·골짜기 표현. `r' = r + A_b · fbm(θ·f_θ, h·f_h)` 로 반경을 흔든 뒤 `h_base(r')`. 경사 국소 변화는 `s_local = s_b + B_b · fbm2(...)`. `A_b, B_b, f` 는 `BiomeDef`. 노이즈는 시드 기반 자체 구현 Perlin/Simplex (`Mathf.PerlinNoise` 는 결정적이지만 오프셋 기준을 우리가 관리해야 하므로 자체 구현 권장 ⚠)
3. **오버행 없음**: 하이트맵이므로 경사 < 90° 보장. 최대 경사 `s_max = 88°` 로 클램프 (등반 탐지 안정성)
4. **발판 스탬프** (노드마다): 셀이 노드 중심에서 `d ≤ r_ledge` 이면 `h = h_node` (평탄). `r_ledge < d ≤ r_ledge + w_fall` 이면 `h = lerp(h_node, h_current, smoothstep((d − r_ledge)/w_fall))`. `w_fall` = 2.5 m ⚠ → 바깥 림은 약 70~80° 벽이 된다 (등반 가능, 걷기 불가). 안쪽은 원뿔이 더 높으므로 깎여서 뒤 벽이 생긴다 → 선반(shelf)
5. **플랫폼 스탬프**: 같은 방식, `r = 22 m`, `w_fall = 4 m`
6. **해변 링**: `r ≥ R_base` 에서 `h = 0` 평탄, `r ≥ R_base + 15` 부터 완만히 −3 m (바다 바닥)
7. **정점 색**: 높이가 속한 밴드의 팔레트 + 경사에 따른 명도 (걷는 면 밝게, 벽 어둡게). **경사 명암 대비는 컷 불가** — 1인칭(`301` D16)에서는 발판이 벽과 구분되지 않으면 길을 읽을 수 없다. 기준: `walkSlope` 경계에서 명도가 뚜렷이 끊긴다 (그라데이션 아님) ⚠. 바이옴 팔레트 색 자체는 컷 가능

스탬프 순서: 원뿔·노이즈 → 플랫폼 → 발판 (뒤가 앞을 덮음). 결정적.

### 4.4 배치

| 대상 | 규칙 |
|---|---|
| 시작점 | 해변 링 위, 첫 플랫폼(`h = 0`, 해변 캠프파이어) 중심에서 3 m |
| 캠프파이어 | 플랫폼 중심. 첫 것은 점화 상태 |

| 정상 표식 | 정상 플랫폼 중심 |

## 6. 솔버 (`RouteSolver`) — 등반 가능성 검증

간선 `A → B` 의 **실제 비용**을 하이트맵 위에서 계산한다 (그래프 상의 이론값이 아니라 노이즈·스탬프가 반영된 최종 지형 기준).

1. 시작점 `a` = A 발판 림 중 B 방향 점 (`A.pos + dir(A→B) · A.r_ledge`), 도착점 `b` = B 발판 림 중 A 방향 점
2. `a → b` 를 수평으로 `0.5 m` 간격 샘플. 각 샘플의 지형 높이 `h_i`, 구간 경사 `θ_i = atan(Δh / Δxz)`
3. 구간 비용
   - 걷기 (`θ_i < walkSlope`): 비용 0 (발판 위 이동으로 취급), 단 **연속 걷기 구간은 휴식으로 인정 = 비용 리셋** ⚠ (2 m 이상일 때만)
   - 등반 (`walkSlope ≤ θ_i ≤ s_max`): 시간 = 구간 길이 ÷ `climbSpeed`, 비용 = 시간 × `climbCost`
   - 하강 (`Δh < 0`, 경사 큼): 비용 0 (떨어져도 됨 — 단 `v_safe` 초과 낙하 높이면 부상 → 경고만)
4. 누적 비용(리셋 사이 최대값) ≤ `100 × safety` 이면 통과. `safety` 0.85 (그래프 생성의 0.7 보다 느슨 — 노이즈 여유)
5. 발판 자체 검사: 노드 중심 반경 `r_ledge × 0.8` 안의 최대 경사 < `walkSlope` (평탄 보장)
6. 전체: 시작 → 정상까지 Main 간선만 따라 연결되어 있고 모든 Main 간선 통과 → **합격**

- 솔버는 `GameTuning` 을 읽는다 (G7). 등반 수치를 바꾸면 자동으로 판정이 바뀐다
- 결과는 `SolveReport` (간선별 비용·통과 여부) → 디버그 기즈모·테스트가 사용

### 6.1 보정 루프

```
for attempt in 0..3:
    build heightfield; report = Solve()
    if report.ok: break
    for each failed Main edge (A→B):
        insert Ledge node at midpoint (표면 위, h = (hA+hB)/2, r = r_min)   // rng 없이 결정적
if !ok: seed' = seed + 1 → 전체 재생성 (로그 경고, 통계 수집)
```

- 목표: 100 시드 중 보정 없이 통과 ≥ 90%, 보정 후 100%, seed+1 폴백 0회

## 7. 결정성 규칙 (G3)

1. 난수는 `System.Random` 만. 단계별 스트림 (3장). `UnityEngine.Random` 금지
2. `Physics.*`, `Time.*`, `Transform` 의존 계산 금지 — 생성은 순수 C# 데이터 → 마지막에 GameObject 생성
3. 부동소수점: 같은 빌드·같은 플랫폼(Windows x64) 가정. `Mathf` 대신 `System.Math`(double) 로 계산 후 float 저장 ⚠ 확인 필요
4. 컬렉션 순회는 `List`/배열만. `Dictionary`/`HashSet` 순회 결과를 생성에 쓰지 않는다
5. `MountainData.Hash()` = 하이트맵 전체 + 노드 목록의 FNV-1a. 호스트와 클라이언트 비교 (`205` 4장) — 불일치 시 경고 후 계속 (개발 중), 릴리스 빌드에서는 클라이언트 재생성 요청 ⚠

## 8. 협동 전용 구간 (T2, `100` 10장 7항)

- 4.2 의 RopeShortcut 간선. 지름길이 있으면 메인 체인 노드 3~5개를 건너뛴다
- 표시: 지름길 아래 발판에 "로프 앵커" 프리팹 (원작의 앵커 지점처럼 눈에 띄게)
- 솔로 경로(메인 체인)는 항상 존재하므로 협동 보장은 "선택지"로만

## 9. v2 — 오버행·동굴 (T2, M6)

- 하이트맵을 유지한 채 **오버행은 별도 메시 오브젝트**로 붙인다 (원뿔 표면 위에 "처마" 프리팹 스탬프). 마칭 큐브 전면 전환보다 싸다
- 동굴: 밴드 하나(Alpine)에 터널 메시 삽입 → 하이트맵에 구멍은 못 뚫으므로 터널은 표면 위 "지붕 있는 통로"로 표현
- 진짜 복셀(마칭 큐브) 전환은 T2 후반 옵션. 등반 탐지(`202` 4장)는 법선 기반이라 그대로 동작

## 10. 디버그 도구 (`Sandbox_ProcGen`, `Peak.Editor`)

| 도구 | 내용 |
|---|---|
| 시드 패널 | 시드 입력, 바이옴 시퀀스 선택, [생성], [다음 시드] |
| 경로 기즈모 | 노드 = 원판 (Platform 파랑 / Ledge 초록 / Decoy 노랑), 간선 = 선 (통과 초록 / 실패 빨강, 비용 라벨) |
| 경사 오버레이 | 정점 색을 경사로 (걷기 / 등반 / 클램프) 토글 |
| 순간이동 | 노드 클릭 → 플레이어 이동 (등반 구간 개별 테스트) |
| 통계 | 생성 시간, 노드 수, 실패 간선 수, 보정 횟수, 해시 |
| 배치 테스트 메뉴 | `Peak > ProcGen > Run 100 Seeds` → 콘솔에 통과율·평균 시간 |

## 11. 테스트 (`Peak.Tests`, EditMode)

- `Generate_100Seeds_AllSolvable`: 시드 1..100 생성, `SolveReport.ok` 전부 true, seed+1 폴백 0회
- `Generate_SameSeed_SameHash`: 같은 시드 2회 → 해시 동일
- `Generate_DifferentSeed_DifferentHash`
- `Generate_Time_Under2s`: 평균 시간 (⚠ 목표치)
- `Ledges_AreFlat`: 모든 노드 발판 최대 경사 < `walkSlope`
- `Tuning_Change_ReflectsInSolver`: `climbCost` 를 2배로 하면 실패 간선이 생긴다 (G7 확인)

## 12. M2 산출물 정의

- `RunConfig` → `MountainData` → 씬에 청크 메시 + 캠프파이어·가방·표식 프리팹 스폰
- `Sandbox_ProcGen` 에서 시드 10개를 눈으로 보고 `BiomeDef` 초기값 확정
- 11장 테스트 전부 통과
- 플레이어를 넣어 시드 1 을 등반 (M1 컨트롤러) → **T0 완주 가능** 이 M2 게이트 (`300`)
- 1인칭으로 발판 위에 서서 **다음 발판이 보이는가** 확인 (경사 명암 대비, 4.3-7). 안 보이면 발판 반경·`Δθ` 보다 대비를 먼저 고친다
